The Mystery of the ClassLoader

Imagine you are doing your homework and need a reference book. How do you find it without wasting time? JVM does the exact same thing using a 3-step search chain!

Step 1: Your Desk

System Class Loader

Checks your personal notebook bag (CLASSPATH)

Looks for custom classes created by you, like MyGame.class or StudentReport.class.

Step 2: Add-On Rack

Extension Class Loader

Checks plugin tools (jre/lib/ext)

Looks for extra shared utility tools, extension packages, and external add-ons installed with Java.

Step 3: Core Vault

Bootstrap Class Loader

Checks core foundation (rt.jar / java.base)

The foundational father-loader written in C/C++. Loads Java's built-in words like String and System.

🎯 The Search Journey: When your code says new Student()

1
System ClassLoader checks your project
Did the programmer write this file in their folder?
Found? → Load into RAM & Run!
↓ Not found in project? Escalate upward
2
Extension ClassLoader checks add-on folders
Is it inside an installed extension/library JAR?

↓ Not found in extensions? Check the core
3
Bootstrap ClassLoader checks Java Core
Is it a foundational Java core class?
Found? → Load into RAM & Run!
↓ Still nowhere to be found?
🚨 ClassNotFoundException Thrown!
The JVM searched your desk, the shelf, and the vault, but the file simply does not exist.
💡 1-Sentence Memory Hook for Exams

JVM searches from Your Desk (System) → to the Rack (Extension) → to the Vault (Bootstrap); if all 3 fail, it raises ClassNotFoundException.
