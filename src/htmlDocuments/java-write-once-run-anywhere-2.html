A little java mystery

Write once.
Run everywhere.

How does one tiny program run on a Windows PC, a Mac, and a Linux machine — without ever being rewritten? Let's follow it, one step at a time.

Fun fact — the Java language is named after coffee.

Step 1

You write the spell

This is HelloWorld.java — the only part a person ever actually reads or writes.

HelloWorld.java 
public class HelloWorld {
    public static void main(String[] args) {
        System.out.println("Hello, World!");
    }
}

Written for people. No computer understands this yet.

javac compiles it — once, on your machine.

Step 2

It becomes a secret scroll

The compiler turns your spell into HelloWorld.class — numbered instructions called bytecode. It isn't English, and it isn't built for any one computer.

HelloWorld.class 
0: getstatic     #7   // System.out
3: ldc           #13  // "Hello, World!"
5: invokevirtual #15  // println
8: return

This exact file is what gets sent anywhere in the world — unchanged.

The same file travels to any computer, as-is.

Step 3

Three robot translators

Every computer keeps its own translator robot, called a JVM. Each one reads that very same secret scroll — and turns it into whatever that computer actually understands.

Windows PC

Reads the scroll. Speaks Windows only.

Mac

Reads the same scroll. Speaks Mac only.

Linux machine

Reads the same scroll. Speaks Linux only.

Three different robots. One shared instruction.

Step 4

Ta-da! Same result, everywhere

Three totally different computers. Same tiny file. Same exact answer.

Windows

> Hello, World!

Mac

> Hello, World!

Linux

> Hello, World!

Write once. Run anywhere.

That's the whole trick — and now you've seen every step of it, from the spell you wrote, to the secret scroll, to the robots who read it.
