The Architecture Blueprint

Java’s Russian Dolls:
JDK vs JRE vs JVM

Why do you need a 300MB download to write Java code, but users only need a smaller runtime to run it? The secret is a hierarchy of three nested layers.

1
Outer Shell

JDK (Java Development Kit)

Target: Developers (Write, Build, Debug)

Development-Only Toolchain (JDK Exclusive)

javac (Compiler)
Translates .java source code into portable .class bytecode
jdb (Debugger)
Inspects memory, sets breakpoints, and steps through executing code
jar / javadoc
Packages archives & auto-generates API reference documentation
2
Middle Shell (Bundled in JDK)

JRE (Java Runtime Environment)

Target: End Users & Servers (Execute Only)

Runtime Libraries & Supporting Files (JRE Exclusive)

Standard Class Libraries (Core API)
Pre-compiled helper classes: java.lang.*, java.util.*, java.io.*
ClassLoaders & Config
Security policies, property files, and binary loaders to bring classes into memory
3
Core Engine (Heart of JRE)

JVM (Java Virtual Machine)

Execution & Platform Independence

The JVM is an abstract computing machine. It reads platform-independent bytecode (.class) and translates it into machine code specific to Windows, macOS, or Linux.

Bytecode Interpreter
Executes bytecode instruction-by-instruction
JIT Compiler
Compiles hot code straight to native machine instructions
Garbage Collector
Automatically reclaims unused heap memory

A Real Code Story: From Text to CPU

Tracing how a single line of code interacts with each layer in sequence.

Phase 1 • Developer Station

Compilation (JDK)

You author Greeter.java. The JRE cannot read source code directly, so the JDK's javac transforms human text into bytecode.

Terminal javac Greeter.java

// Greeter.java -> Greeter.class

CA FE BA BE (Magic number for Java bytecode)

Phase 2 • Assembly & Context

Linking Libraries (JRE)

Your code uses System.out.println(). Your class file doesn't define that—the JRE's Core Class Libraries provide the real implementation.

Runtime Dependency Resolution
Greeter.class + rt.jar / java.base.jmod
→ Standard Out streams, memory bindings, OS hooks verified
Phase 3 • Execution

Machine Execution (JVM)

The bytecode is executed inside the JVM. It translates platform-agnostic commands into physical binary instructions tailored to that exact CPU architecture (x86_64, ARM64, etc.).

Native Output (OS Layer)
JVM -> CPU [MOV, PUSH, SYSCALL]
> "Hello from Java!"
